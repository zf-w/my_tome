## Fixing Windows 11 VM "Display Resources Error"

When using a GPU on the Windows 11 VM with KVM, Qemu, and Virt-manager, the screen would suddenly disappear.

After some discussion with GPT (via duck.ai), it seemed the problem was related to "virtio-vga." GPT identified the issue by reviewing an XML output and noting that "virtio-vga" looked a bit unusual.

```bash
sudo virsh domxml-to-native qemu-argv PATH_TO_XML_IN(/etc/libvirt/qemu) | tr ' ' '\n' virsh domxml-to-native qemu-argv win11.xml | tr ' ' '\n'
```

# Wednesday, July 29th

## GPU Passthrough

### Checking IOMMU Groups

```bash
#!/bin/bash
shopt -s nullglob
for g in $(find /sys/kernel/iommu_groups/* -maxdepth 0 -type d | sort -V); do
    echo "IOMMU Group ${g##*/}:"
    for d in $g/devices/*; do
        echo -e "\t$(lspci -nns ${d##*/})"
    done;
done;
```

Initially, I used the following script, based on my assumption of how the directory structure worked. However, it didn't work correctly and listed most devices under Group 0:

```bash
for d in /sys/kernel/iommu_groups/*; do 
	echo "Group ${d##*/}:"
	echo "$(lspci -nns ${d##*/})"
done;
```

### Letting "vfio" grab the GPU

1. Get the device identifiers:

```bash
lspci -nnk # e.g., [1234:1234]
```

2. Ensure the "vfio" driver loads for the GPU devices early: 

```bash
options vfio-pci ids=XXXX:XXXX,XXXX:XXXX
```

3. Block certain drivers like "nouveau."

4. Check whether the "vfio" driver grabs the passthrough devices early. Some parts of the blacklist might not be necessary; I may research this further later.

```
# Inside /etc/default/grub
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash rd.driver.blacklist=nouveau modprobe.blacklist=nouveau video=vesafb:off iommu=pt intel_iommu=on"
```

```
# Inside /etc/modprobe.d/blacklist.conf
blacklist i915
blacklist nvidia
blacklist nvidia_drm
blacklist nvidiafb
blacklist nvidia_modeset
blacklist nvidia_nvm
blacklist nvidia_wmi_ec_backlight
blacklist nouveau
options nouveau modeset=0
```

5. Update GRUB and initramfs.

```bash
sudo update-grub
sudo update-initramfs -u
```

6. Verify whether the "vfio" driver managed to grab the devices.

```bash
dmesg | grep -i vfio
```

# Wednesday, July 15th

## Setting Up GitHub SSH

- Connect to GitHub with SSH, https://docs.github.com/en/free-pro-team@latest/authentication/connecting-to-github-with-ssh

1. Generate a new SSH key.

  ```bash
  ssh-keygen -t ed25519 -C [YOUR_EMAIL@EXAMPLE.COM] -f [PATH_TO_KEY_FILE]
  ```

2. Add your SSH key to the ssh-agent

  ```bash
  eval "$(ssh-agent -s)" # Get the agent pid

  ssh-add [PATH_TO_YOUR_PRIVATE_KEY_FILE] # Use "chmod 400" to secure the file from other users.

  ```

3. Copy the Generated Public Key to GitHub

  ```bash
  cat [PATH_TO_YOUR_PUBLIC_KEY_FILE] # Copy this to your GitHub SSH field.
  ```

4. Verify SSH Connections to GitHub

  ```bash
  ssh -T git@github.com # Attempts to SSH to GitHub

  # Check GitHub's public key fingerprints from verified sources, for example https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection
  ```
